# tg-botik

Telegram-бот с расписанием метро и командами FACEIT.

## Запуск

Установите [uv](https://docs.astral.sh/uv/getting-started/installation/), затем из корня репозитория выполните:

```sh
uv sync --locked
```

Создайте файл `.env` в корне проекта и укажите токен бота:

```dotenv
BOT_TOKEN=your_telegram_bot_token
FACEIT_API_KEY=your_faceit_api_key
```

`FACEIT_API_KEY` нужен для команд FACEIT. При необходимости можно задать `FACEIT_GAME` (по умолчанию `cs2`) и `FACEIT_ACCOUNTS_PATH` (по умолчанию `data/faceit_accounts.json`).

Запустите бота:

```sh
uv run --locked python src/app.py
```

Зависимости меняются командой `uv add <пакет>` или `uv remove <пакет>`; `uv` обновит `pyproject.toml` и `uv.lock`. После этого обновите также прямые зависимости в `requirements.txt`, который использует Bothost.

## Деплой на Bothost

В [форме создания бота](https://bothost.ru/create-bot.php) укажите:

| Поле | Значение |
| --- | --- |
| Название | `tg-botik` (или любое удобное) |
| Платформа / библиотека | Telegram / aiogram |
| Bot Token | Токен от BotFather; Bothost передаст его как `BOT_TOKEN` |
| Git URL | `https://github.com/shynkaaaa/tg-botik.git` |
| Ветка | `main` |
| Дополнительные настройки → Главный файл (точка входа) | `src/app.py` |
| Использовать собственный Dockerfile | Выключено |

Сначала отправьте текущие изменения в выбранную ветку Git. Bothost установит зависимости из корневого `requirements.txt` и запустит `src/app.py` как Python-скрипт. Бот получает обновления через long polling; домен, порт и webhook для него не нужны. Если панель предлагает выбрать версию Python, укажите 3.11 или новее.

В разделе «Переменные окружения» добавьте `FACEIT_API_KEY`, если используете команды FACEIT. `FACEIT_GAME` необязательна (по умолчанию `cs2`). Токен задавайте через поле **Bot Token**; `.env` и реальные ключи в Git не загружайте. Пример локальных переменных находится в `.env.example`.

Если используете команды со списком аккаунтов FACEIT, загрузите `faceit_accounts.json` через файловый менеджер Bothost в `/app/data/`. Код ищет его по этому пути автоматически; каталог `data/` не хранится в Git. Формат файла: JSON-объект с полем `accounts`, содержащим объект аккаунтов.

Перед запуском остановите прежний экземпляр этого же бота, чтобы два процесса не выполняли polling с одним токеном. Создайте бота или выполните новый деплой после изменения настроек. Статус, логи сборки и логи работы смотрите в панели управления ботом. При ошибке установки пакетов проверяйте логи сборки, при падении процесса — логи работы.

**Тариф для постоянной работы:** на [странице тарифов Telegram](https://bothost.ru/telegram-bots) бесплатный Start указан со спящим режимом, а Active — с работой 24/7 без сна. Для непрерывного polling нужен тариф без сна. При этом [общая страница бесплатного хостинга](https://bothost.ru/free-hosting) обещает 24/7; сведения Bothost противоречат друг другу, поэтому перед выбором бесплатного тарифа уточните режим сна в панели или у поддержки.
